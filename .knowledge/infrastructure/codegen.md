# Code generation

**Rule: TypeScript for wire types is generated or it does not exist**
(decision-1). Hand-written wire types are a review blocker.

## Pipeline

1. `rpc_contract!` in `crates/protocol` declares each request, its
   identically tagged success shape, and its desktop/mobile/web-extension
   targets. The macro emits `RpcMethod`, `RpcResult` and `RPC_OPERATIONS`—one
   registry, not a matching list in xtask.
2. `pixi run xtask codegen` exports every wire type via
   ts-rs 12's `Config` API (`.with_large_int("number")`—request ids are
   small, `bigint` would tax every caller) into
   `packages/protocol/src/generated`.
3. Xtask writes the barrel and `version.ts` from the Rust constant, exports
   the WASM-facing `OtpAuthInfo`, then filters `RPC_OPERATIONS` into committed
   `DesktopClient`, `MobileClient` and `WebExtensionClient` classes under
   their apps. Shared operations are generated repeatedly; domain-only
   operations appear only on their named face. Every class extends the one
   `RpcClient` mechanics layer in `packages/core`.
4. The same command reads `apps/extension/native-hosts/host.json` and emits
   Chromium/Firefox manifests plus the host-name constant used by the
   extension transport. Browser-specific allowlist fields can therefore not
   drift while the host identity stays one value.
5. Output is committed. Generator-owned directories are cleared before every
   run so removed types cannot linger. `pixi run codegen-check` regenerates and
   rejects tracked changes or untracked outputs; CI runs that gate before
   typechecking.

## The two-doors problem and its fix

ts-rs `#[ts(export)]` generates a hidden test per type that writes to
`TS_RS_EXPORT_DIR` (default: `./bindings` inside the crate) on every
`cargo test` — polluting the repo. Root `.cargo/config.toml` redirects it
to the shared generated directory, so `pixi run cargo test -p castellan-protocol`
and xtask produce **identical bytes**. A crate-local `.cargo/config.toml`
does not work — cargo reads config cwd-upward from the invocation dir, not
from the crate being tested.

## WASM side-channel

`@castellan/wasm` wraps wasm-pack output for the extension's pure logic
(origin matching, otpauth validation). Built by `pixi run wasm` into
`src/pkg`: JavaScript and WASM stay ignored, while wasm-bindgen's declaration
files are committed and checked for zero diff in CI. The loader is typed with
`typeof import("./pkg/castellan_wasm.js")`; `OtpAuthInfo` is generated by
xtask from the Rust struct, so the wrapper carries no second declaration of
either surface. It still throws a readable "run pixi run wasm" error when the
runtime artifact is missing.

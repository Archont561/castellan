# Styling

Atomic utilities from **UnoCSS**, generated per consumer from **one shared
config** — `unoPreset()` in `@castellan/utils/uno`, next to the bunup and
playwright presets for the same reason. No component framework ships CSS
into the bundle; what a face downloads is the utilities its own source
actually uses.

## The shape

| Piece | Where | Why there |
| --- | --- | --- |
| Tokens (`--bg`, `--fg`, `--accent`, `--muted`, `--surface`, `--border`, `--danger`, `--ok`, `--font-sans`) | preflight in the shared preset | they used to be a `:root` block duplicated in two `app.css` files; one copy is one place to edit |
| Theme colours | `var(--token)`, not inlined hex | overriding a variable on a subtree re-themes every utility built from it — the thing the original `app.css` comment promised and inlined colours cannot do. The cost: `/50` opacity shorthand does not work on token colours |
| `currentColor` tints | custom rules `bg-/text-/border-/stroke-tint-<n>` | every hairline and secondary label was already a hand-written `color-mix(in oklab, currentColor n%, transparent)`; as a rule the percentages cannot drift between components |
| Component looks | shortcuts: `c-entry-row`, `c-badge`, `c-field`, `c-action`, `c-section-title`, `c-ring-track`, `c-ring-progress` | the faces share a *look* |
| Metrics (padding, width, radius) | utilities in the markup | the faces legitimately disagree about *size* — a desktop row is denser than a touch target, the mobile action is full-width with a 10px radius |

A consumer's `uno.config.ts` is two lines: `export default unoPreset()`.
The only option is `shell`.

## `shell`: who owns the page

`shell: true` (default) adds the `html`/`body` preflight — the dark surface,
full height, the font stack. The two SvelteKit faces own their window and
want it.

`shell: false` is the extension popup and the library's own harnesses
(Storybook, Playwright component tests): they render *into* a surface
somebody else owns, and a popup that paints a full-bleed background fights
the browser's chrome. They still get the tokens, because the utilities
resolve against them.

## The extraction pipeline is the fragile part

`@castellan/ui` is consumed as **source** (no build step; the apps compile
the `.svelte` files). So the shared components are part of the *consuming
app's* module graph, and their classes have to be generated by the
*consuming app's* UnoCSS pass. The shared config's `content.pipeline`
therefore includes `packages/ui/src` — matched by path, in both the
real-path and the `preserveSymlinks` form — and excludes everything in
`node_modules` that is not `@castellan/*`.

The failure mode if that include ever stops matching is nasty precisely
because it is partial: the components keep compiling, keep passing their
component tests, and keep looking right in Storybook (which runs its own
UnoCSS pass over the same sources) — and arrive in the apps with class
attributes and no CSS. `packages/utils/test/uno.test.ts` pins the pipeline
patterns and the generated declarations so the regression is a failing unit
test rather than a design review.

Two smaller traps found while building it:

- **An unmatched utility inside a shortcut is a warning, not an error.**
  `transition-[stroke-dashoffset]` has no arbitrary-value form in
  presetWind3; UnoCSS logged one line and emitted the shortcut without a
  `transition-property`, which would have transitioned *all* properties of
  the TOTP ring at one second. Arbitrary *properties* (`[stroke-width:2.5]`,
  `[transition-property:stroke-dashoffset]`) are the reliable escape hatch.
- **The extractor tokenises whole files, comments included.** The words
  "ring" and "grid" in component documentation each matched a real
  presetWind3 utility and shipped rules nothing references; both are in the
  config's `blocklist`, which does not affect the shortcuts that expand to
  `display: grid`.

## Test and e2e hooks are not styling

Every styled element keeps its bare semantic class first — `username`,
`badge`, `status`, `error`, `progress`. Those carry no CSS. They exist so
`packages/ui/tests/*` and the faces' e2e suites can query something that a
design change cannot break, which is also what let the whole migration land
without touching a single test selector.

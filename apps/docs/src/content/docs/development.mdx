## Prerequisites

Install [pixi](https://pixi.sh), then run `pixi install`. The committed
`pixi.lock` supplies Bun, Rust with clippy and rustfmt, the wasm32 target,
wasm-pack, convco, actionlint, cargo-deny, cargo-nextest, and cargo-llvm-cov.
Rust and Bun retain mirror pins in `rust-toolchain.toml` and `package.json`,
but direct rustup/bun execution is not a supported repository command path:
hooks, CI, and contributors all enter through `pixi run`.

The Tauri desktop app additionally needs the platform webkit libraries
(`libwebkit2gtk-4.1-dev` and friends on Linux — the lists are in
`.github/workflows/ci.yml`).

## The daily loop

```console
$ pixi run install                  # once: JS deps for every workspace
$ pixi run codegen              # regenerate wire types, clients and host manifests
$ pixi run codegen-check        # regenerate and prove committed output is current
$ pixi run wasm                 # rebuild the WASM package for the extension
$ pixi run gates                # lint + typecheck + test, every language

$ pixi run e2e              # browser e2e: desktop, mobile, extension
$ pixi run storybook-build        # build the ui package's Storybook
$ pixi run dev-storybook        # Storybook dev server (packages/ui)

$ pixi run dev-desktop          # tauri dev (apps/desktop)
$ pixi run dev-mobile           # tauri dev (apps/mobile)
$ pixi run dev-extension              # wxt dev (chromium; :firefox for gecko)
$ pixi run dev-docs             # this documentation site

$ pixi run cargo test --workspace       # the Rust suites directly
$ pixi run xtask codegen
```

`gates` is the same command CI runs, through the same turbo graph: Rust
runs once as one node in the JS task graph (the `@castellan/rust`
façade), TypeScript fans out per package.

## Conventions worth knowing

- **Commits** are Conventional-Commits, enforced by the lefthook
  `commit-msg` hook; changelogs are generated from them.
- **Rust dependencies** are declared in the root `[workspace.dependencies]`
  with a reason, never inline in a crate. `[workspace.lints]` applies
  `missing_docs`, clippy `all`, and `unsafe_code = "forbid"` to every
  member.
- **TypeScript projects** extend the bases from `@castellan/utils`:
  packages `lib.json` (+ bun types), apps their framework config *and*
  `app.json` via extends-arrays. (This docs app is the one exception —
  it extends Astro's strict base, because Starlight needs Astro's
  client types.)
- **The `@` alias** is each workspace member's own root (`@/src/…`),
  wired per stack: tsconfig `paths` in packages, `kit.alias` in the
  SvelteKit apps (tsc *and* vite), WXT's generated config in the
  extension, tsconfig paths here (Astro reads them). It is for tests
  and app source — never for a shared package's `src/`, whose files are
  bundled by the consuming app, where `@` means *that* app.
- **Library packages build with bunup**, their configs two lines around
  the shared `libPreset` from `@castellan/utils`: ESM + declarations to
  a gitignored `dist/`, workspace dependencies external. The artifact
  proves bundleability (and is the future publish output); workspace
  consumers still import `src/`.
- **Browser tests are one Playwright and one chromium.** All playwright
  packages are pinned to the same version (the last line of
  `@playwright/experimental-ct-svelte`), and the browser is a root
  devDependency — `@playwright/browser-chromium` downloads it during
  `pixi run install`, so there is no `playwright install` step anywhere. See
  [Testing](/testing) for the shapes: app e2e, component tests, and the
  `playwright-cli` agent workflow.
- **Adding a crate**: a directory under `crates/` with a manifest that
  inherits, a line in root `[workspace.dependencies]`, a row in
  `crates/README.md`. The glob does the rest.
- **Adding a protocol operation**: add one `rpc_contract!` entry with request
  fields, success fields and its desktop/mobile/web-extension targets; add
  one implementation arm in `crates/dispatch`, and one exhaustively keyed
  arbitrary in the protocol property suite; run `pixi run codegen`. Xtask
  writes the correlated wire DTOs and every selected app client—never edit
  those generated files or add a dispatch match to an app shell.

`AGENTS.md` in the repository root is the full contract for agents and
humans working in this tree: the invariants, the commands, the
conventions, and what is deliberately not there yet.

## The documentation site you are reading

`docs/` is a workspace member: Astro + Starlight, served by
`pixi run dev-docs`, built by `pixi run docs-build` (CI builds it on
every push). Pages are MDX under `docs/src/content/docs/`; the sidebar is
hand-written in `docs/astro.config.mjs` — a generated sidebar documents
the file tree, not the reading order.
